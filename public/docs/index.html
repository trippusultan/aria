Get started

Aria developer documentation

Aria reads the meetings and mail you connect, suggests action items with the exact quote they came from, and tracks the ones you accept against the people involved. These pages cover the REST API and how each part behaves.

QuickstartSign up, load sample data and list tasks in five requests. API referenceEvery endpoint, parameter and response shape. ExtractionWhat counts as an action item, and how excerpts stay verbatim. Privacy modelIsolation, encryption at rest and what admins can never see.

Design principles

  • Confirm before commit. Extracted items are suggestions until the user accepts them. The assistant only proposes changes.
  • Source is sacred. Every captured task links to the meeting or email and a verbatim excerpt.
  • Private by default. Every record belongs to one user. There is no org-wide content API.
  • Precision over coverage. The extractor abstains when unsure.

Base URL

All endpoints are relative to the Aria host, for example http://localhost:4180. Requests and responses are JSON unless an endpoint says otherwise.

Get started

Quickstart

Run Aria locally, create an account, pull in demo meetings and mail, and read back the suggested actions.

1. Run the server

Aria needs Node 22.13 or newer and has no dependencies.

cd aria
npm start          # http://localhost:4180

2. Create an account

Sessions are cookies, so keep a cookie jar. Every request with a body must send Content-Type: application/json.

curl -c jar -b jar http://localhost:4180/api/auth/signup \
  -H 'Content-Type: application/json' \
  -d '{"email":"sam@example-bank.test","password":"choose-a-long-one","name":"Sam Carter"}'

3. Load sample data

Sample data is a set of fictional meetings, email and calendar events. It needs no provider credentials. (/api/connectors/:type/connect is for real accounts and returns 409 until the provider is set up.)

curl -b jar -X POST http://localhost:4180/api/sample-data \
  -H 'Content-Type: application/json' -d '{}'

4. Read the inbox

curl -b jar http://localhost:4180/api/suggestions
[{
  "id": 1, "confidence": 0.9, "state": "pending",
  "source": { "id": 1, "type": "meeting", "title": "Northwind weekly", "started_at": "2026-09-26T10:40:00.000Z" },
  "payload": {
    "title": "Send revised term sheet with prepayment cap",
    "owner": "user", "direction": "i_owe",
    "stakeholders": [{ "name": "Ananya Shah", "email": "ananya.shah@northwindcap.com", "unverified": false, "person_id": 1 }],
    "due": { "date": "2026-10-01", "span": "by Thursday" },
    "excerpt": "I'll turn the term sheet around by Thursday with the prepayment cap we discussed.",
    "confidence": 0.9, "rationale": "User made an explicit first-person commitment"
  }
}]

5. Accept one and list tasks

curl -b jar -X POST http://localhost:4180/api/suggestions/1/accept \
  -H 'Content-Type: application/json' -d '{}'
curl -b jar http://localhost:4180/api/tasks

Get started

Authentication

Aria uses session cookies. There are no API keys. Every call acts as the signed-in user and sees only that user's data.

Session cookie

  • POST /api/auth/signup or /api/auth/login sets aria_sid (HttpOnly, SameSite=Lax; Secure when ARIA_SECURE_COOKIE is set).
  • Sessions expire after 12 hours idle. Each authenticated response refreshes the cookie.
  • List and revoke sessions with /api/sessions.

Request requirements

RuleWhy
Requests with a body must be Content-Type: application/jsonBlocks cross-site form posts
A cross-origin Origin header gets 403CSRF defence alongside SameSite
Bodies are capped at 1 MBAbuse protection

An unauthenticated request to any /api/* route returns 401 {"error": "..."}.

Get started

Errors & limits

Errors are JSON objects with one field, error, and a matching HTTP status.

{ "error": "At least one stakeholder is required" }
StatusMeaning
400Validation failed. The message names the field.
401Not signed in, or the session expired.
403Cross-origin request, or not an admin for admin routes.
404Not found. This is also what you get for another user's record: Aria never confirms that it exists.
409Conflict, for example an email already registered or an assistant proposal already applied.
413Body over 1 MB.
429Rate limited. See below.

Rate limits

EndpointsLimit per IP
/api/auth/signup, /api/auth/login20 per 15 minutes
/api/export/*20 per hour

Pagination

List endpoints are not paginated: they return the user's full set, already filtered by your query. Aria holds one person's work, typically hundreds of tasks, not millions. Two lists are capped at the newest entries:

EndpointReturns
GET /api/notificationsNewest 100
GET /api/audit, GET /api/admin/auditNewest 500

Use filters (status, due, person, q) rather than fetching everything and filtering client-side.

Versioning

The API is pre-1.0 and unversioned: paths have no /v1 prefix, and shapes may change between releases. CONTRACT.md in the repository is the binding spec. Responses may gain fields; clients should ignore fields they don't know.

Concepts

Tasks, suggestions & sources

Four objects carry the whole product.

ObjectWhat it is
SourceA meeting, email or pasted text Aria processed. Holds participants and the raw text, encrypted.
SuggestionA candidate action the model found in a source, with a verbatim excerpt and a confidence. It is not work yet.
TaskConfirmed work: title, status, direction, due date, stakeholders, notes, activity, and a link to its source.
PersonA stakeholder. Resolved from calendar attendees and email headers, otherwise marked unverified.

Direction

Every task records who owes whom: i_owe (the user owes the stakeholder), they_owe, or unclear. When the model can't tell who owns an item it says owner: "unclear" rather than guessing.

The Task object

{
  "id": 12, "title": "Send revised term sheet with prepayment cap", "body": "",
  "status": "open", "direction": "i_owe", "due_at": "2026-10-01", "priority": null,
  "tags": [], "visibility": "private",
  "stakeholders": [{ "id": 1, "display_name": "Ananya Shah", "unverified": false, "role": "counterparty" }],
  "source": { "id": 1, "type": "meeting", "title": "Northwind weekly", "started_at": "2026-09-26T10:40:00.000Z" },
  "excerpt": { "text": "I'll turn the term sheet around by Thursday…", "start_offset": 212 },
  "notes_count": 1, "last_note": "Legal wants to see the cap language first",
  "created_at": "…", "updated_at": "…"
}

Concepts

Status lifecycle

StatusMeaning
suggestedOnly exists as a pending suggestion. Never a task status.
openAccepted; not started.
in_progressBeing worked on.
waitingBlocked on a stakeholder.
completedDone. Kept for history and search.
cancelledNo longer relevant. Kept for history.

GET /api/tasks without a status filter returns everything except completed and cancelled. Every change is written to the task's activity log.

Concepts

Privacy & security

The API enforces these rules, not just the UI.

  • Isolation. Every record is keyed by user. A request for another user's record returns 404.
  • Encryption at rest. Source text, excerpts, suggestion payloads, notes, assistant threads and connector tokens are encrypted with AES-256-GCM under a per-user key. Deleting the account destroys the key.
  • Admins see metadata only. Seats, connector status, counts and admin-action audit. No admin endpoint returns titles, notes, excerpts or text.
  • Read-only connectors. Aria never sends mail or writes to calendars.
  • Delete means delete. A deleted source never returns on the next sync. Raw text is wiped after the retention window (default 90 days).
  • No autonomous actions. Assistant changes require an explicit confirm call.

API reference

Auth & account

POST/api/auth/signup

Create an account and start a session. The admin role goes only to emails the operator lists in ARIA_ADMIN_EMAILS.

BodyType
emailstringRequired
passwordstring8–200 characters
namestringRequired, ≤100

Returns { user } and sets the session cookie. 409 if the email exists.

POST/api/auth/login

Body { email, password }. Returns { user } and sets the cookie. Rate limited.

POST/api/auth/logout

Ends the current session.

GET/api/me

The signed-in user plus home-screen counts.

{ "user": { "id": 1, "email": "sam@example-bank.test", "name": "Sam Carter", "role": "admin" },
  "counts": { "open": 3, "waiting": 0, "overdue": 0, "suggested": 3 },
  "can_setup": true, "demo": true, "push": false }

can_setup is true when this user may configure provider OAuth apps: an admin, or anyone on the server's own machine when ARIA_ADMIN_EMAILS is empty.

GET/api/sessions

Devices signed in: [{ id, user_agent, ip, created_at, last_seen_at, current }].

DELETE/api/sessions/:sid

Revoke one session. :sid is the 64-character id from GET /api/sessions.

DELETE/api/account

Body { password }. Removes every task, note, source, person and connector token for the user and destroys their encryption key. Audit events are kept without content.

API reference

Tasks

GET/api/tasks

List the user's tasks. Filters combine. Sorted by direction, then due date (empty last), then most recently updated.

QueryValues
statusComma list of open,in_progress,waiting,completed,cancelled. Default: all except completed/cancelled.
personPerson id
source_typemeeting · email · manual
dueoverdue · today · week · none, using the user's timezone
directioni_owe · they_owe · unclear
tagTag text
qSearch across title, notes, stakeholder names and source title
curl -b jar 'http://localhost:4180/api/tasks?status=open,waiting&due=week'

POST/api/tasks

Create a task by hand. Body: title (required), body, direction, due_at (YYYY-MM-DD), priority (low|med|high), tags, stakeholders ([{person_id}] or [{name}]; a new name creates an unverified person), source_id.

GET/api/tasks/:id

A task plus notes: [{id, body, created_at}] and activity: [{verb, from_value, to_value, at, actor}].

PATCH/api/tasks/:id

Update any of title, body, status, direction, due_at, priority, tags, stakeholders. Send null to clear due_at or priority. Each change is logged.

curl -b jar -X PATCH http://localhost:4180/api/tasks/12 \
  -H 'Content-Type: application/json' -d '{"status":"completed"}'

POST/api/tasks/:id/notes

Append a note: { body }. Notes can't be edited or deleted.

POST/api/tasks/:id/duplicate

Copy a task. Returns the new task.

DELETE/api/tasks/:id

Delete a task.

API reference

Suggestions

The inbox: candidate actions waiting for a human decision. A rejected suggestion never becomes a task.

GET/api/suggestions

Pending, not snoozed, highest confidence first. See the example payload.

POST/api/suggestions/:id/accept

Turn a suggestion into an open task. Optional edits: {title, direction, due_at, stakeholders, body}. 400 if no stakeholder would remain.

POST/api/suggestions/:id/reject

Optional reason: not_action or never_happened. Rejected titles teach this user's extractor what isn't an action.

POST/api/suggestions/:id/merge

Body { task_id }. Appends the excerpt as a note on an existing task.

POST/api/suggestions/:id/snooze

Body { hours }. Hidden until then.

POST/api/suggestions/bulk-accept

Accept every pending suggestion at or above the user's high_threshold (default 0.85) in one transaction. Invalid items are skipped. Returns { accepted }.

API reference

Connectors

Types: zoom, gmail, outlook, gcal, mscal.

GET/api/connectors

[{ type, label, status, mode, configured, setup, scopes, last_sync_at, last_error }]. mode is oauth, demo (sample data) or null. When configured is false, setup lists the env vars, redirect URI, console link and scopes needed.

POST/api/connectors/:type/connect

Returns { redirect }: send the user there. The provider returns to /oauth/:type/callback. Returns 409 when the provider is not configured on the server. It never falls back to sample data.

POSTDELETE/api/sample-data

Load fictional meetings and email (optional { types }, default gcal, zoom, gmail), or remove them. Removing keeps tasks you accepted. Loading returns 409 if a real account of that type is connected.

POST/api/connectors/:type/sync

Sync now. Connected connectors also sync every 60 s.

DELETE/api/connectors/:type

Revoke. Tokens are wiped and ingest stops immediately, including a sync already in progress.

Assistant

A query and drafting layer over the user's own tasks and sources. It never changes data on its own.

POST/api/assistant

Body { message, thread_id? }.

{
  "thread_id": 4,
  "reply": "Mark this task as completed? Nothing changes until you confirm.\n• Send revised term sheet with prepayment cap — due Thu 1 Oct · Zoom · Northwind weekly [#1]",
  "citations": [{ "task_id": 1, "title": "Send revised term sheet with prepayment cap", "source_title": "Northwind weekly" }],
  "proposals": [{ "id": "b6208c1d7aa3", "action": "set_status", "task_id": 1, "args": { "status": "completed" },

Proposal actions: set_status, add_note, set_due, create_task.

POST/api/assistant/confirm

Body { thread_id, proposal_id }. Applies the proposal and returns { ok, task }. This is the only way an assistant change happens. A second confirm returns 409.

GET/api/assistant/threads/:id

The stored conversation.

Guides

Connecting Zoom, Gmail & Outlook

Each provider needs an OAuth app registered once per server. After that, every user connects in one click.

ProviderEnv varsScopes (read-only)
ZoomZOOM_CLIENT_ID, ZOOM_CLIENT_SECRETcloud_recording:read, user:read
Google (Gmail, Calendar)GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRETgmail.readonly, calendar.readonly
Microsoft (Outlook, Calendar)MS_CLIENT_ID, MS_CLIENT_SECRETMail.Read, Calendars.Read, offline_access

Set up a provider

  1. Open Settings → Connections as an admin. On a fresh install with no ARIA_ADMIN_EMAILS, anyone browsing from the server's own machine counts.
  2. Expand the provider's setup guide. It lists the console steps and the exact redirect URIs (<ARIA_BASE_URL>/oauth/<type>/callback) to paste.
  3. Paste the client ID and secret and save. They are stored encrypted with the server key and take effect immediately (PUT /api/admin/providers/:type).

Alternatively set the env vars above and restart. Env vars win over pasted values.

After setup, POST /api/connectors/:type/connect returns { redirect } to the provider's consent screen. Tokens are stored encrypted under the user's key.

Ingest behaviour

  • Meetings with no transcript become a no_transcript source you can add actions to by hand.
  • Newsletters, excluded labels and meetings on excluded calendars are skipped.
  • Calendar events add attendees to meetings, so stakeholders resolve to real people.

The provider fetchers have not been run against real accounts yet. Try a sandbox tenant first.

Guides

How extraction works

Aria looks for commitments, requests and dated follow-ups that involve the user, and ignores everything else.

What counts

  • The user commits ("I'll send the revised memo").
  • Someone asks the user, and the user doesn't refuse.
  • The user asks someone else and expects something back.
  • A dated follow-up is agreed ("Let's reconvene Friday").

What's ignored

  • Small talk, status narration and FYI.
  • Hypotheticals ("we could consider…").
  • Other people's work that doesn't involve the user.

Two engines

With ANTHROPIC_API_KEY set, Aria asks Claude for structured candidates, then checks each one on the server. Without it, a deterministic rule engine runs. Either way:

  • Excerpts must be a verbatim substring of the source (at least 20 characters) or the candidate is dropped.
  • Due dates must round-trip and their justifying words must appear in the text.
  • Candidates below low_floor are dropped. Titles the user already rejected are not suggested again.
  • Dates are resolved relative to the meeting's local day in the user's timezone.

Guides

Assistant grounding

The assistant answers from the user's tasks and sources only, and says so when it finds nothing.

With Assistant and AI turned on, Jev (TypeSafe) decides what you asked and which task, person or meeting you meant. The answer is still built only from your own records.

AskBehaviour
"What is pending?" · "What is overdue?" · "What is due this week?"Lists real tasks, each cited with its title and source
"What is open with Ananya?"Only tasks linked to that person
"What came out of Northwind weekly?"Tasks and excerpts from that source
"Draft a follow-up to Ananya about the term sheet"A draft to copy. Aria never sends it.
"Mark the term sheet done" · "Add a note…" · "Move … to Friday"A proposal that needs confirm
"Show me Priya's emails" · "Say I promised…" · "Join the meeting"Refused

Deploy

docker build -t aria . && docker run -p 4180:4180 -v aria-data:/data \
  -e ARIA_MASTER_KEY=<64 hex> -e ARIA_ADMIN_EMAILS=you@company.com -e ARIA_SECURE_COOKIE=1 aria

Serve it behind HTTPS. GET /api/healthz returns {"ok":true} without auth, for load balancers.
